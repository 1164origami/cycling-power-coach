# 多源数据与主观反馈驱动的骑行教练流程

> 适用：用户已授权COROS、高驰、Intervals.icu等工具；本仓库本身不提供API连接。**任何健康数据和完整GPS轨迹只在授权会话里读取，不写入公开仓库。**

## 1. 数据来源与优先顺序

| 决策环节 | 优先证据 | 不能推断的内容 |
|---|---|---|
| 骑行事实 | 实际运动记录：日期/当地时间、距离、moving/elapsed时长、功率、心率、路线 | 没有记录 ≠ 没有日常活动 |
| 历史负荷 | ICU 的CTL/ATL/TSB（统一在同一平台比较） | CTL下降90%≠体能下降90%；TSB正值≠完全恢复 |
| 单次训练压力 | ICU的power load/TSS与COROS的训练负荷各自报告 | **不同平台单位/算法不可直接相加或等价比较** |
| FTP | 有日期、方法和有效功率数据的测试/持续努力 | 账号设置值、停训后滚动eFTP不代表新实测FTP |
| 体征 | 当天的睡眠、静息心率、HRV（注明记录日期、覆盖率） | 没戴表或尚未同步则「缺失」，不能填0或套用前一晚 |
| 运动员反馈 | 疼痛、麻木、RPE、心情、补水补给、旅行与工作压力 | 设备显示「Fresh」不能否决具体身体症状 |

## 2. 去重与口径核查

1. 以运动当地开始时间（可容忍秒级时钟差）、时长、距离和GPS相似性识别同一次活动；重复同步的COROS与ICU记录只算一次。
2. 分清 elapsed/moving/pedalling 时间、平均功率与NP、FTP的适用日期，功率单位W、心率bpm、爬升m、液体mL。
3. 记录平台数据新鲜度：今天健康数据可能未同步；HRV若无数据不做异常解释。
4. 骑行分析区分：直接观测、平台计算、模型估计、主观报告、教练推测。
5. 心率-功率解耦只在足够长、相对稳定的功率/环境下可靠。高VI、红绿灯多、强爬坡、补给骤变时不能把数值当作有氧阈值诊断。
6. 任何实测数据出现明显冲突先回查功率来源、设备时间与运动记录，不虚构缺失分段。

## 3. 训练决策的安全门槛

- **红灯**：运动中反复出现/持续恶化的腰椎正中痛、手麻或无力、会阴麻木，或者胸痛、晕厥、严重运动后肌痛/深色尿。停止运动；必要时医疗评估或急诊。
- **黄灯**：前一日骑到明显力竭、局部仍有疼痛、睡眠不足、RHR明显偏离个人基线、较长停训后首骑。优先休息/日常轻活动；只有完全不诱发症状时才考虑短低负荷试骑。
- **绿灯**：连续日常活动无痛、无麻木，短骑可正常交谈，次日状态不恶化，才逐渐增加时长或距离。
- 多种信号冲突时，**症状和安全高于模型恢复度**；不得仅根据94–100%恢复度安排长距离。

## 4. 给用户的固定分析输出

1. 当前目标与距离单位（100km还是100mi），还有多少可骑行时间。
2. 数据日期、来源、真实记录、空值与口径。
3. 最重要的1–3个变化（功率保持、心率反应、骑姿/局部痛、补给、睡眠）。
4. 训练建议主方案+疲劳或疼痛时的备选降级方案；明确停止标准。
5. 下一次运动要验证的2–4项指标（RPE、后半程功率趋势、坐垫/腰背/手部症状、次日反应）。

**只读默认**：未经明确同意，不更改任何平台的运动日历、FTP设置、运动记录或路书。
